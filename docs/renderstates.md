# Named render states (`Scene::init_render_states`) and how the D3D11 backend consumes them

Status: ✅ table decoded and cross-checked against the decompile · ✅ backend mapping read from `d3dgl.dll` · 🟡 a few legacy bits unexplained (see open questions)

Machine-readable form: `re/iface/renderstates.json` (generated by `node re/tools/renderstates.mjs [gameDir] [--md]`; `--md`
prints the table in section 2). The generator parses `re/decomp/renderstate/Scene_init_render_states@008ba450.c` and reads
names from the user's `Data/internal_strings.xml`, so it ships no game text of its own.

## 0. What a `RenderState` is

`RenderState` (rise.pdb, 0x168 bytes, `bighuge:renderstate.obj`) is a D3D7/8-style fixed-function state block: an `enables`
bit field, depth func and bias, blend factors, alpha test, stencil, cull/fill/shade, a texture factor colour, two texture
stages (op + two args for colour and alpha, texcoord index, address modes, filters, mip bias), fog parameters, clip-plane
constants, UV deltas and a legacy "pixel-shader situation" map. The same class is compiled into `d3dgl.dll`.

`Scene::init_render_states` @008ba450 allocates **50** states into the global `render_states` array, runs
`RenderState::init` on each (defaults below), then customises each one by index. Game code mostly uses the states by
**index** (`render_states[i]`); data files use them by **name**.

Defaults (`RenderState::init` @00535ba0): `enables = 0x3` (depth test + depth write), `zfunc = LESSEQUAL`, `zbias = 0`,
`tfactor = 0xFFFFFFFF`, fill SOLID, shade GOURAUD, cull CCW, blend ONE/ZERO, alpha func ALWAYS ref 0, stencil ALWAYS/KEEP
with masks 0xFF, stage 0 = `MODULATE(TEXTURE, CURRENT)` colour and `SELECTARG1(TEXTURE)` alpha, texcoord 0, stage 1 =
DISABLE/DISABLE with texcoord 1, both stages WRAP, POINT mag/min, no mip, bias 0, fog off (start 0, end 1, density 0.5, black).

### Name resolution

- The name of state *i* is `String::operator=(&state->name, int_str_array.strings + OFF)`. `int_str_array` is the
  internal string table loaded from `Data/internal_strings.xml`; its element type is `String` (0x14 bytes), so
  **`OFF / 0x14` is the 0-based index of the `<STRING>` element in file order** (no filtering: all 7,630 entries have
  `needed="1"`, and the hash attribute is not involved). Verified on every name: offsets 0x1b4b8…0x1b940 land on
  "Unit Blend" (#5590) … "Surf Wave Blend" (#5648), plus "Wireframe Blend" at 0x5aa0 (#1160). The same rule decodes the
  pixel-shader names (e.g. 0x1b4cc = `ps_luminance_CBTAtf_CxA4tf`) and "Nuke" (0x2788, #506).
- Lookup by name is an exact, linear `String ==` over `render_states` (e.g. `GraphicPieces::init_ammo_data`,
  `init_pulsewave_data`, `init_sniper_effect`, `init_particle_params`, `Underlays::init_class`); a miss reports "Invalid RS".
- `renderstate="…"` in `effects_graphics.xml` (AMMO, AGEn, ENTRENCH, FLAG, DEBRIS, SCAFFOLD, MOVEMARKER, UNDERLAY,
  PULSEWAVE, SNIPERPIECE) – every value resolves to a table entry, **except** WAVESECTION, which `Surf::init_class` resolves
  against its own list `{"Wash", "Crash", "Wave"}` (internal strings #6270–6272) and maps to state index `47 + i`
  (Surf Wash/Crash/Wave Blend).
- Particles (`PARTICLERENDER blend="…"`, `GraphicPieces::init_particle_params`) look up the attribute value, with
  `" Shadow"` appended for the shadow pass (giving "Smoke Blend Shadow"). Values used: Smoke Blend, Fire Blend, Ammo Blend.
  One entry is `"Smoke Blend    "` with trailing spaces, which does not match exactly (see open questions).

### Texture args (colorarg1/2, alphaarg1/2)

Plain ints in the exe; `TextureColorArg` in d3dgl.pdb. **Not** the D3D `D3DTA_*` numbering:

| Value | RenderState name | d3dgl `TextureColorArg` | HLSL macro (`color_arg_lookup`) | D3D9 equivalent |
|---|---|---|---|---|
| 0 | Current | COLOR_ARG_CURRENT | `COLOR_CURRENT` (= `outColor`); **stage 0 remaps it to DIFFUSE** | D3DTA_CURRENT (1) |
| 1 | Diffuse | COLOR_ARG_DIFFUSE | `COLOR_DIFFUSE` (= vertex colour, or 1.0 when the vertex has none) | D3DTA_DIFFUSE (0) |
| 2 | SelectMask | COLOR_ARG_SELECTMASK | `COLOR_DIFFUSE` (aliased) | — |
| 3 | Specular | COLOR_ARG_SPECULAR | `COLOR_SPECULAR` (vertex specular or 1.0) | D3DTA_SPECULAR (4) |
| 4 | Temp | COLOR_ARG_TEMP | `COLOR_TEMP` (always 0 in the shader) | D3DTA_TEMP (5) |
| 5 | Texture | COLOR_ARG_TEXTURE | `COLOR_TEXTURE(n)` = `tex1`/`tex2` (sample of t0/t1) | D3DTA_TEXTURE (2) |
| 6 | TFactor | COLOR_ARG_TFACTOR | `COLOR_TEXFACTOR` (= `gTexFactor`) | D3DTA_TFACTOR (3) |
| 7…13 | — | `*_COMPL` | `COMPLEMENT(x)` = `1 - x`. An arg with bit 31 set (D3DTA_COMPLEMENT style) becomes `(arg & 0x7fffffff) + 7` | |

No named state uses a complemented arg.

### `enables` bit field

There is no enum for it in either PDB; meanings come from the consumers in `d3dgl.dll`. The exe only sets and clears
bits; a scan for `TEST [reg+0x50], bit` over the unexplained bits (0x20, 0x40, 0x100, 0x400, 0x800, 0x1000, 0x2000) and
0x20000/0x400000 found no reader in the exe.

| Bit | Meaning | Consumer (d3dgl) |
|---|---|---|
| 0x1 | depth test enable | `set_depth_stencil_state`: DepthEnable |
| 0x2 | depth write (only effective together with 0x1) | DepthWriteMask = ALL iff `(enables & 3) == 3` |
| 0x4 | alpha blending enable | `set_blend_state`: BlendEnable |
| 0x8 | stencil enable | StencilEnable (no named state uses it) |
| 0x10 | fog | adds `ENABLE_FOG`, which **no shader reads** (fog is not implemented in EE) |
| 0x80 | alpha test | adds `ENABLE_ALPHA_TEST`, sets `gAlphaTestValue = alpha_ref / 255` |
| 0x200 | lighting | adds `ENABLE_LIGHTING` only while the context's light switch (`mEnableLight`) is on |
| 0x800 | ? (Reflection Blend only) | not read anywhere; legacy (possibly an old clip-plane enable) |
| 0x4000 | normal map | `USE_NORMAL_MAP`, only if the vertex format has tangents (vert flag 0x2000000) |
| 0x80000 | animated water normals | `ANIMATE_WATER_NORMALS` (only inside 0x4000) |
| 0x8000 | specular map | `USE_SPEC_MAP` |
| 0x800000 | diffuse texture as specular colour | `DIFFUSE_AS_SPEC` (only inside 0x8000) |
| 0x10000 | gloss map | `USE_GLOSS_MAP` |
| 0x20000 | "TL fake light" | `TL_FAKE_LIGHT`: unlit path brightens `pow(c, 1.9) * hdrMultiplier` and scales alpha by `gTLAlpha` |
| 0x40000 | UV scroll | `DELTA_UV` (`gUVDelta0/1`, which come from the *Material*, not the RenderState) |
| 0x100000 | Torrance–Sparrow specular | `SPEC_MODEL_TORRANCE` |
| 0x200000 | screen-space reflections | `HAS_SCREEN_REFLECTIONS`; binds depth and back-buffer copies to PS t5/t6 |
| 0x400000 | point sampling | sampler filter MIN_MAG_MIP_POINT instead of anisotropic |
| 0x1000000 | point sprite | `POINT_SPRITE` (also enables the geometry shader `gs_global.hlsl`) |
| 0x2000000 | nuke flash | `NUKE_FLASH` |
| 0x20, 0x40, 0x100, 0x400, 0x1000, 0x2000, ≥0x4000000 | unused | |

Common values in the table: `0x84` = blend + alpha test, no depth; `0x87` = depth test/write + blend + alpha test;
`0x85` = depth test without write + blend + alpha test; `0x20084/0x20085/0x20087` = the same plus TL_FAKE_LIGHT;
`0x287` = 0x87 + lighting. The code edits them as `(enables & ~2) | X` (drop depth write) or `(enables & ~3) | X` (no depth).

### Scalability flags (rise.pdb `Scalability`, `graphsys->scalability`)

Only two are read here: `bad_team_color` (+0x74) changes stage 1 of **Unit Blend**, and `is_SiS` (+0x6c) lowers the alpha
reference of **Team Color Blend** by one. Others in the struct (`is_3dfx`, `force_disable_pshaders`, `force_bw_cursors`,
`prevent_bit_depth_toggle`) are not used by this function.

### Special cases and runtime changes

- **Unit Blend, `bad_team_color`:** normally stage 1 colour = `MODULATE(CURRENT, DIFFUSE)`; on cards flagged
  `bad_team_color` it becomes `SELECTARG2(TEXTURE, CURRENT)` (pass stage 0 through), dropping the vertex-colour modulation.
- **Team Color Blend:** `alpha_ref = 248`, or 247 when `scalability.is_SiS`. Together with Building Blend (`NOTEQUAL 248`)
  and Blocked Building Blend (`GREATEREQUAL 248`), this uses texture alpha 248 as a team-colour mask key.
- **Lighting toggle:** `GraphicPieces::on_field_change` (and the same code in `GraphicPieces::init`) sets or clears bit
  0x200 on **Unit Blend (0)** and **Death Blend (3)** from the `light_units` setting. So Death Blend can be lit at runtime
  even though `init_render_states` does not set it.
- **Building Blend (26):** `Camera::update_render_states` / `Camera::update_transforms` force its stage 0 mag/min filter to
  POINT. This has no effect on the D3D11 backend.
- **tfactor is per-draw on several states:** `GraphicPieces::draw_build` (buildings, also writes `GREY`), `draw_ammo`
  (Ammo Team Blend), `draw_skeleton`, `flush_trees` (Tree Blend) and `ConquestGraphicPieces::draw` (Unit Blend) overwrite
  the shared state's tfactor before drawing. The tfactor carries the team colour (`BLENDTEXTUREALPHA(TEXTURE, TFACTOR)`
  puts the player colour where texture alpha is low) and fades (`MODULATE4X(..., TFACTOR)` on alpha).
- **Pixel-shader "situations" (legacy, dead in EE):** 27 states call `add_pshader_situation`, mostly
  `("Nuke", "ps_luminance_…")` and, for Reflection Blend, a default `ps_CtAtf_KillT0`. They map a situation name to a
  precompiled `.pso` from `all_pshaders`. The install contains no `.pso` files and `D3D11GLSys::set_situation` is a folded
  no-op stub, so a port can ignore them (they are kept in the JSON as `pixelShaderSituations`).
- **Game code users:** `usedBy` in the JSON lists the functions that index each state directly (from
  `re/iface/renderstate_users.json`, a heuristic grep of the 64 functions that reference `render_states`). The states
  with no direct users are reached by name from XML (Smoke/Fire/ZFire, Ammo, Scaffold, Moveto, river/surf/wake underlays,
  Sniper Scope) or through `surf_texture_rs_index` (47–49).

Other `RenderState` objects exist outside this table and are not covered here: statics in `worldmap.obj`
(fog/who/solid/back/blip), `Nuke.obj` (noise, shroom smoke, fire particle, impact, scorch), `RiverDoobers::riv_doob_rs`,
`BoundingVolume::bvolume_renderstate`, `ConquestMap::init_render_states`, `IFaceRenderManager::setup_render_states`,
`ScriptEditBox::init_render_state`, and in d3dgl `D3D11GLSprite::def_render_state` / `def_mip_render_state`.

## 3. How `d3dgl.dll` turns a RenderState into GPU state

`GSGraphicCard::set_render_state` (vtable slot at +0x24) is `D3D11GLGraphicCard::set_render_state` @1002b2f0. Unless
the card is locked (`lock_renderstate`), it:

1. If bit 0x200000: binds the reflection manager's depth and back-buffer SRVs to PS slots 5–6.
2. **Rasterizer** (`set_rasterizer_state` @1002b410, cached by `cull<<4 | fill<<6`): FillMode via `d3d11FillModeLookup`
   = {NONE→SOLID, POINT→WIREFRAME, WIREFRAME→WIREFRAME, SOLID→SOLID}; CullMode via `d3d11CullModeLookup` = {NONE→NONE,
   CW→BACK, CCW→FRONT}; **FrontCounterClockwise = TRUE**; depth bias 0; DepthClipEnable TRUE; no scissor/MSAA/AA lines.
   That is D3D9 semantics: CULLMODE_CCW removes counter-clockwise triangles.
3. **Depth-stencil** (`set_depth_stencil_state` @1002b5f0, cached by a 64-bit key): DepthEnable = bit 0x1; write mask
   ALL iff bits 0x1 and 0x2; DepthFunc = `d3d11ComparisonLookup[zfunc]` (= value + 1; out-of-range → NEVER); StencilEnable =
   bit 0x8, with the same ops/func for front and back faces, read/write masks = low byte of `stencil_mask` /
   `stencil_write_mask`, and `stencil_ref` passed to `OMSetDepthStencilState`.
4. **Blend** (`set_blend_state` @1002b900): one render target, BlendEnable = bit 0x4, SrcBlend/DestBlend =
   `d3d11BlendModeLookup` (identity: the enum already equals `D3D11_BLEND`), BlendOp ADD, **SrcBlendAlpha = ONE,
   DestBlendAlpha = ZERO, BlendOpAlpha = ADD** (destination alpha is overwritten with source alpha), write mask RGBA,
   blend factor (1,1,1,1), sample mask all. The cache key is `dst | (src | blendEnable<<1) << 4`. The enable bit overlaps
   bit 1 of `src`, so "disabled, ONE/x" and "enabled, ONE/x" share an entry. That is harmless in the named table (the only
   collision is Wireframe Blend against the ONE/ZERO states, which give the same pixels), but don't copy the key.
5. **Samplers** (`set_sampler_states` @1002bb60, both stages, cached by `addrU<<12 | addrV<<8 | point<<6`): Filter =
   ANISOTROPIC with MaxAnisotropy 16, or MIN_MAG_MIP_POINT when bit 0x400000; AddressU/V = `d3d11TextureAddressLookup`
   (value + 1: WRAP, MIRROR, CLAMP, BORDER, MIRROR_ONCE); AddressW = CLAMP; MipLODBias 0; LOD range unlimited; border
   colour 0. **The RenderState's mag/min/mip filters and `mipmap_bias` are ignored.**
6. **Shaders** (`set_shader_options` @1002db30, details below).
7. `D3D11Context::set_tfactor`: `gTexFactor = (r, g, b, a) / 255` (PerMaterial cbuffer b2).
8. `gDepthBias = (float) zbias` (PerMaterial). **Depth bias is done in the vertex shader, not the rasterizer:** for 3D
   geometry the view-space z is reduced by `8 × gDepthBias` before projection; for screen-space (pre-transformed) vertices
   the output z is reduced by `gDepthBias`.
9. Records the state as current (`mCurrentState`) and copies it into the system's shadow RenderState.

Also ignored by the backend: `shade_mode`, `fog_*`, `clip_plane_constants`, `index_vblend`, `delta_uv0/1`, and the pixel-shader
situations.

### Shader permutation (`set_shader_options`)

The backend builds a list of `ShaderCompilationOptions`, each turned into a `#define NAME 1` from `shaderMacroNames`
(`PHOENIX_SHADER_COMPILE` is always first). Sources and resulting macros:

| Source | Macro |
|---|---|
| always | `PHOENIX_SHADER_COMPILE` |
| enables 0x200000 / 0x2000000 / 0x1000000 | `HAS_SCREEN_REFLECTIONS` / `NUKE_FLASH` / `POINT_SPRITE` |
| `GSGraphicCard::minimap_mode` (byte at +0x10), set only by `WorldMapBackground::render` for the minimap texture | `NO_HDR` |
| card `mUseTL` (pre-transformed vertices) | `TRANSFORM_SCREEN_SPACE` |
| enables 0x10 / 0x80 | `ENABLE_FOG` / `ENABLE_ALPHA_TEST` |
| vertex format: diffuse / specular / UV0 / UV1 / UV2 / xyz position | `ENABLE_VERTEX_COLOR_DIFFUSE` / `_SPECULAR` / `USE_UV0..2` / `POSITION_XYZ` |
| enables 0x4000 (+ tangents) [+0x80000], 0x8000 [+0x800000], 0x10000, 0x20000, 0x40000 | `USE_NORMAL_MAP` [`ANIMATE_WATER_NORMALS`], `USE_SPEC_MAP` [`DIFFUSE_AS_SPEC`], `USE_GLOSS_MAP`, `TL_FAKE_LIGHT`, `DELTA_UV` |
| enables 0x200 and lighting on | `ENABLE_LIGHTING` |
| enables 0x100000 | `SPEC_MODEL_TORRANCE` |
| `tex_coord_index[0] == 1` / `tex_coord_index[1] == 1` | `TEX0_UV1` / `TEX1_UV1` (the default stage-1 index is 1, so most states emit `TEX1_UV1`) |
| a stage's colour args reference a texture but no texture is bound | `TEX0_NOT_BOUND` / `TEX1_NOT_BOUND` |

The vertex and geometry shaders get only these option macros. `D3D11PixelShader::compile` @1003fc50 adds the
texture-stage macros (stage 0 → `TS1_*`, stage 1 → `TS2_*`):

- `TSn_COLOROP` / `TSn_ALPHAOP` = `TEXOP_<OP>(n, COLOR|ALPHA)` from `texop_lookup` (`SUBTRACT` is spelled `SUBSTRACT`).
- `TSn_COLORARG_1/2`, `TSn_ALPHAARG_1/2` = `color_arg_lookup[arg]` with `$NUM0` = n, after the stage-0 CURRENT→DIFFUSE remap.
- `ALPHA_TEST_FUNC` = `TEST_<func>` from stage 0's alpha func (it is only expanded when `ENABLE_ALPHA_TEST` is defined).
- `TS_STAGES` = "0" if stage 0's colour and alpha ops are both DISABLE, "1" if only stage 0 is active, "2" if stage 1 is
  active too (stage 1 is not counted when stage 0 is disabled).
- `HAS_TEX0` / `HAS_TEX1` if any arg of that stage is TEXTURE (or its complement).

Compilation: `D3DCompile(ps_global.hlsl, "PS", "ps_4_0", OPTIMIZATION_LEVEL3)` (VS: `vs_global.hlsl` / `vs_4_0`; GS
`gs_global.hlsl` / `gs_4_0` only for POINT_SPRITE). Compiled shaders are cached: the VS by the 64-bit option mask, the PS by
`{option mask, stage-0 key, stage-1 key}`, where a stage key packs colorop, colorarg1/2, alphaop, alphaarg1/2 and the
alpha func into two dwords. Option→mask bits come from `remapShaderLookup`; **bug:** index 31 (`NUKE_FLASH`) maps to
0x04000000, the same bit as `TEX0_NOT_BOUND`, so those two permutations can collide in the cache.

What the uber-shader does with the stage macros (`shader_texture_data.h`, paraphrased): `outColor` and `outAlpha` start as
1.0 and `temp` as 0. With `TS_STAGES >= 1`, `outColor = TS1_COLOROP`, `outAlpha = TS1_ALPHAOP`, then
`outColor.a = outAlpha.a`; with `TS_STAGES >= 2` the same for TS2 (where `COLOR_CURRENT` is now stage 1's result). The
result is `float4(outColor.rgb, outAlpha.a)`, saturated. All args are float4, so the alpha op is evaluated on full vectors
and only `.a` is kept. The ops are the D3D9 formulas: SELECTARGn = argn; MODULATE{,2X,4X} = a1·a2·{1,2,4};
ADD = a1+a2; ADDSIGNED = a1+a2−0.5; ADDSIGNED2X = 2(a1+a2−0.5); SUBTRACT = a1−a2; ADDSMOOTH = a1+a2(1−a1);
BLEND{DIFFUSE,TEXTURE,FACTOR,CURRENT}ALPHA = lerp(a2, a1, alpha of that source) (TEXTURE uses the stage's own texture);
BLENDTEXTUREALPHAPM = a1 + a2(1−tex.a); the four MODULATE…ADD… ops are the D3D9 ones; DOTPRODUCT3 = dot(a1.rgb, a2.rgb).
PREMODULATE outputs a debug green. BUMPENVMAP, BUMPENVMAPLUMINANCE, MULTIPLYADD and LERP have **no HLSL macro** (they
would fail to compile), and DISABLE as an op returns `COLOR_CURRENT` / `ALPHA_CURRENT`. The named states use only
SELECTARG1/2, MODULATE/2X/4X, ADDSIGNED, BLENDTEXTUREALPHA and DISABLE.

Then the pixel shader applies lighting or TL_FAKE_LIGHT, HDR scaling (×5 unless `NO_HDR`; `pow(c, 1.45)` before lighting),
`OUT.Color = max(0, color)`, and the alpha test as `clip()` against `gAlphaTestValue` (`EQUAL` uses a ±0.0001 epsilon;
NEVER is `discard`). Samplers: stage 0 = `t0`/`s0`, stage 1 = `t1`/`s1`, material map `t2` (sampled with s0), reflection
depth/back buffer `t5`/`t6`. A stage's texcoord is `uv1` when `TEXn_UV1` and the vertex has UV1, else `uv0`; with neither,
`HAS_TEXn` is undefined and the texture reads as 1.0.

## 4. Metal mapping (implementation recipe)

Per `RenderState` (plus the vertex format and card flags) build:

- **`MTLRenderPipelineDescriptor` key** = blend (enable, src, dst) + pixel-shader permutation + vertex layout. Colour
  attachment: `blendingEnabled = (enables & 4)`, `rgbBlendOperation = .add`, source/destination RGB factor from
  `BlendMode` (ZERO→.zero, ONE→.one, SRCCOLOR→.sourceColor, INVSRCCOLOR→.oneMinusSourceColor, SRCALPHA→.sourceAlpha,
  INVSRCALPHA→.oneMinusSourceAlpha, DESTALPHA→.destinationAlpha, INVDESTALPHA→.oneMinusDestinationAlpha,
  DESTCOLOR→.destinationColor, INVDESTCOLOR→.oneMinusDestinationColor, SRCALPHASAT→.sourceAlphaSaturated), alpha factors
  **.one / .zero** with `.add`, write mask `.all`. When blending is off, also write all channels.
- **`MTLDepthStencilDescriptor`**: `depthCompareFunction` = zfunc (NEVER→.never … ALWAYS→.always) if bit 0x1 else
  `.always`; `isDepthWriteEnabled = (enables & 3) == 3`. Stencil only for bit 0x8 (unused by the named table).
- **Encoder state** per draw: `setFrontFacing(.counterClockwise)`; `setCullMode` NONE→.none, CW→.back, CCW→.front;
  `setTriangleFillMode(.lines)` for POINT/WIREFRAME; no `setDepthBias` (bias goes into the vertex shader's
  `gDepthBias` uniform). If the Metal port keeps D3D's clip-space conventions (same projection, y-up NDC, viewport
  y-flip) the winding is unchanged; if it flips y in the projection, swap the cull faces.
- **Samplers** (one per stage): `.linear` min/mag/mip with `maxAnisotropy = 16`, or `.nearest` everywhere for bit
  0x400000; `sAddressMode`/`tAddressMode` WRAP→.repeat, MIRROR→.mirrorRepeat, CLAMP→.clampToEdge,
  BORDER→.clampToBorderColor (transparent black), MIRRORONCE→.mirrorClampToEdge; `rAddressMode = .clampToEdge`. Ignore the
  RenderState filter fields, as the original does.
- **Fragment function**: port `ps_global.hlsl` to MSL once and specialise with function constants (or preprocessor
  macros) using exactly the macro set in section 3. `renderstates.json` → `d3d11.shaderDefines` gives the RenderState part
  for every state (the vertex-format macros and `NO_HDR`/`TRANSFORM_SCREEN_SPACE` are added at draw time). The alpha
  test becomes `discard_fragment()` in the shader; MSL has no `clip()`.
- **Uniforms** (PerMaterial): `gTexFactor` (tfactor bytes /255, red first), `gAlphaTestValue = alpha_ref/255`,
  `gDepthBias = zbias`, plus the Material fields (`gUVDelta0/1`, `gTLAlpha`, ambient/diffuse/specular/emissive/power).

The JSON's `metal` object carries this mapping per state (`colorAttachment`, `depthStencil`, `cullMode`,
`frontFacingWinding`, `triangleFillMode`, `sampler[2]`).

## Open questions

1. Bit 0x800 (Reflection Blend) has no reader in the exe or in d3dgl. It is probably a dead D3D7-era flag (clip plane?);
   the port can ignore it, but it is worth a look if reflections misbehave (Reflection Blend also uses cull CW and tfactor
   alpha 0x4f).
2. ~~The `NO_HDR` source~~ Resolved: it is `GSGraphicCard::minimap_mode`, set only around the minimap render-to-texture
   (`WorldMapBackground::render`). The main view always compiles with HDR. See [lighting-spec.md](lighting-spec.md).
3. `"Smoke Blend    "` (trailing spaces) in one PARTICLERENDER does not match by exact compare unless `XMLElement::get_attrib`
   trims. If it does not, that particle system keeps a null or previous render state. Check `get_attrib` or the runtime.
4. Particles with the shadow flag append `" Shadow"`; only "Smoke Blend Shadow" exists, so a shadowed Fire/Ammo particle
   would not resolve. Check whether any shipped particle sets that flag with those blends.
5. `TEX0/1_NOT_BOUND` is decided with a loose bit test (`(arg1 | arg2) & 5`, colour args only), so stages whose args are
   DIFFUSE/SPECULAR/TFACTOR also count as "uses a texture" when nothing is bound. Mirror it or fix it deliberately.
6. Runtime tfactor values (team colours, fades, GREY for buildings) come from the draw functions listed above; their
   exact colour sources are not decoded here.
7. `ENABLE_FOG` is emitted but unused, and the original EE has no distance fog. Confirm against a screenshot before
   adding fog to the port.
